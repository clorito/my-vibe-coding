学习笔记

Vibe Coding 学习路上攒下的套路和心得，持续更新。

01好提示词五要素

  • ① 做什么（文件/页面）② 有哪些内容 ③ 长什么样（风格）④ 技术限制（单文件/复用公共 CSS）⑤ 给谁用
  • 要素越全，一次到位率越高，省 Coding Plan 额度
模板：做一个 ___（页面），包含 ___（内容），风格 ___（深色/浅色/参考某页），限制 ___（单文件/复用 style.css），给 ___ 用。

02精准反馈：描述差异，不说"感觉不对"

  • 说清楚"现象是什么、我预期是什么、请改哪里、其他部分不动"
  • 一次只提一个修改，改完立刻刷新验收，再提下一个
模板：功能对，但是 ___（现象）和我预期 ___ 不一样，请修改 ___，保持其他部分不动。

03先出计划，再动手

  • 需求稍复杂时，让 AI 先给实现计划，确认后再写代码
  • 好处：能看懂思路、及时纠正方向、避免大返工
模板：请先给我一个实现计划，我确认后再写代码。

04CSS 变量：一处改，全站变

  • 主题色放 :root 的变量里（--theme 实色 + --theme-rgb 半透明用），引用它的地方才会跟着变
  • 写死的颜色不会跟随主题——发现漏网之鱼就统一改成 rgba(var(--theme-rgb), …)

05存明细，不存汇总

  • 汇总（总数）可以从明细（每次记录）算出来，反过来不行
  • 案例：打卡计数器只存了 count，想加"查看记录"功能时历史已无法找回

06Git 三件套

  • git status 看改了什么 → git add . 送上待存档台 → git commit -m "说明" 咔嚓存档
  • 节奏：改完一个功能 → 浏览器验收 → 满意就 commit → 再下一个（小步提交，随时可回退）
偷懒模板：帮我提交当前所有改动，commit 信息用中文概括这次改了什么。

07GitHub 推送避坑（大陆网络）

  • 主页能开 ≠ git 能推：网页 200 但 push 卡死是常态，遇到先重试，十有八九能过
  • 命令挂着一分钟不动 = 握手卡死，停掉重试比干等强；别乱改配置
  • 设备码授权只做一次，凭证会存进 Windows 凭据管理器，以后 push 不再弹窗
  • 节奏：commit 随时可做（本地），push 遇到网络问题随时补，两者互不影响
