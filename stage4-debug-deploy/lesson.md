# Stage 4 · 调试、测试、部署上线（第 4 周）

## 目标
学会三件事：出了问题怎么让 AI 排查（调试）、怎么让 AI 帮你写自动化检查（测试）、怎么把应用放到互联网上（部署）。

## Day 1：调试 —— 报错是最好的线索

新手最重要的一课：**把报错原样贴给 AI，不要只说"报错了"**。

万能调试提示词：
```
运行 xxx 时出现如下报错，请：
1. 用人话解释这个报错在说什么
2. 分析可能的原因（按可能性排序）
3. 给出修复方案并直接修改代码
报错信息：
（原样粘贴完整的报错文本和截图）
```

练习：`samples/buggy.html` 里有 3 个 bug。打开它，按 F12 打开浏览器控制台，
把红色报错贴给 ZCode 逐个修好（目标：点添加能出条目、点删除能删掉、刷新不丢数据）。

## Day 2：测试 —— 让 AI 帮你写自动验收
```
请给 stage3 的待办应用写一个简单的自动化测试（可以用 Node 自带的测试能力或 vitest），
覆盖：添加待办、勾选完成、删除、筛选逻辑。写完教我怎么运行测试。
```
以后每次让 AI 改完代码，都可以补一句：「跑一遍测试，全绿再交给我」。

## Day 3：部署静态网页（免费，5 分钟）
最简单的上线方式：
```
请带我把 stage1 的个人主页部署到 GitHub Pages，让别人能通过网址访问。每一步先解释。
```
完成后把链接发给朋友 —— 你的第一次上线。

## Day 4：部署带后端的应用
```
stage3 的 todo-app 有 Node 后端。请推荐一个对新手最友好的免费部署方案
（比如 Render / Railway / Vercel），并带我从零部署上去，包括怎么让线上也有数据存储。
```
注意：免费的数据库方案（如 Render 磁盘、SQLite 云方案）让 AI 帮你选并讲清限制。

## Day 5：上线后巡检
```
我已部署到 <你的网址>。请帮我检查：
1. 用代码或工具验证所有 API 是否正常响应
2. 列出上线应用常见的 3 个安全隐患，我的应用有没有
```

## samples/ 说明
`samples/buggy.html`：故意埋了 3 个 bug 的待办页面，Day 1 的调试靶子。

## 验收清单
- [ ] buggy.html 的 3 个 bug 都修好
- [ ] 有至少 4 个自动化测试且全部通过
- [ ] 个人主页通过 GitHub Pages 可公开访问
- [ ] （进阶）待办应用已部署上线
